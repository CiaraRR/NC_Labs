Methods and parameters

A method packages a task for reuse. Parameters are typed names in its declaration; arguments are the actual values supplied by a call. Match their types and order.

static void greet(String visitor) {
  System.out.println("Welcome " + visitor);
}
// call: greet("Alex");

Returning a value

void performs a task without returning a value. A value-returning method declares its result type and uses return. Its caller can store or use that result.

static double half(double value) {
  return value / 2;
}
// call: double result = half(15);

Further topics

Overloading uses the same method name with different parameter lists. Recursion calls the same method with a smaller problem and needs a reachable base case. Strings are indexed from zero; use length() and charAt(index).

Detailed walkthrough

Design a method around one responsibility

Give each method a clear purpose: read input, validate a value, calculate a result, or display information. A small method is easier to test and reuse than a method that mixes every task together.

Its declaration states modifiers, return type, name and parameter list. A void method performs a process without producing a result value for its caller. A value-returning method declares the type of that result.

Keep helper declarations inside the class but outside other method bodies. In these examples, static helpers can be called directly from static main without creating a separate object.

Worked example: arguments and returned values

Consider static int triple(int value) { return value * 3; }. The declaration introduces the formal parameter value. In int answer = triple(5);, the argument 5 supplies its value for that call.

The helper returns 15 to the caller, which stores it in answer. Printing inside a method is different: visible output does not by itself provide a returned value that the caller can use in a calculation.

Try a second call with another argument. Each call has its own parameter values and local variables. Use a trace that separates the caller’s variables from the method’s variables.

Validation, overloading and recursion

A Boolean helper can describe a rule and return whether it holds. Decide whether a reading method repeats until valid input or returns an input for the caller to validate. Make that responsibility clear.

Overloaded methods share a name but have different parameter lists. Argument types and order determine which applicable overload is selected. A different return type alone is not enough to distinguish two declarations with identical parameters.

A recursive method calls itself. Identify its base case, ensure the recursive input moves toward it, and check which inputs are supported. A base case designed only for positive integers may not terminate for zero or negative input.

Strings, testing and practice

String character positions start at zero. A loop examining every character uses a condition that stops before length(). Character comparisons are case-sensitive unless the program deliberately normalises case.

Practice: create a void greeting method, a value-returning calculation, and a Boolean validation method. Call each with several inputs. Then trace a small recursive calculation without running it.

Self-check: identify formal parameters and actual arguments, explain why return differs from println, and describe the exact input that stops a recursive example.
